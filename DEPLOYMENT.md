# Публикация: GitHub → Posit Connect Cloud

Инструкция проверена по документации Posit 29 октября 2026 года. На GitHub хранится код, а Connect Cloud запускает R и обслуживает посетителей. Компьютер автора после публикации может быть выключен.

## 1. Что именно загружать

Используйте **только содержимое папки `BE_Calculator_Web`** как отдельный репозиторий. В корне репозитория должны лежать `app.R`, `renv.lock`, папки `R` и `www`.

Не загружайте весь родительский аналитический проект. Локальные папки `.Rlibrary`, `.renv-cache`, журналы и токены не нужны; они перечислены в `.gitignore`.

Рядом с этой папкой подготовлен архив `BE_Calculator_Web_GitHub.zip`: это чистый комплект для загрузки без установленных пакетов. Архив содержит файлы приложения в корне. Перед загрузкой через сайт GitHub **распакуйте его**: загрузка одного ZIP в репозиторий не создаёт нужную структуру приложения.

## 2. Локальная проверка

1. Откройте `BE_Calculator_Web.Rproj` в RStudio.
2. Выполните в консоли R:

```r
source("scripts/setup.R")
source("tests/verify.R")
source("scripts/run_local.R")
```

В этой подготовленной копии пакеты уже установлены локально. На другом компьютере `setup.R` восстановит их по `renv.lock`.

Для стандартного сценария оставьте 2×2, CV Cmax = 25%, CV AUC = 20%, мощность 80%, выбывание 10%. Ожидаются **N = 28** для анализа и **N = 32** для включения.

## 3. Создание репозитория GitHub

Для бесплатной публикации из GitHub в Connect Cloud репозиторий должен быть **Public**. Это означает, что исходный код и логотип будут открыты всем.

Самый простой вариант через сайт:

1. Войдите в [GitHub](https://github.com/) и выберите **New repository**.
2. Назовите его, например, `be-calculator`, выберите **Public**, создайте репозиторий.
3. Выберите **uploading an existing file** либо **Add file → Upload files**.
4. Перетащите файлы и папки из распакованного чистого архива. В репозитории `app.R` должен оказаться в корне, а не внутри ещё одной папки.
5. Нажмите **Commit changes**.
6. Проверьте наличие `app.R`, `renv.lock`, `R/calculations.R`, `www/farm_logo.png`.

Если предпочитаете Git, создайте на сайте пустой публичный репозиторий **без автоматически созданного README**. Затем в PowerShell, находясь в подготовленной папке:

```powershell
git init -b main
git add .
git status
git commit -m "Prepare BE calculator for public hosting"
git remote add origin https://github.com/YOUR_LOGIN/be-calculator.git
git push -u origin main
```

Замените `YOUR_LOGIN` своим логином. Перед коммитом в `git status` не должно быть `.Rlibrary`, `.renv-cache`, `.Renviron` или токенов. GitHub при необходимости предложит авторизацию. Эти команды приведены для нового отдельного репозитория; повторно `git init` для последующих обновлений не нужен.

## 4. Подключение Posit Connect Cloud

1. Откройте [Posit Connect Cloud](https://connect.posit.cloud/) и создайте аккаунт или войдите. Для начала выберите **Free**.
2. На главной странице нажмите **Publish**, выберите публикацию **From GitHub** и тип **Shiny**.
3. Если сервис предложит установить GitHub App, разрешите доступ к репозиторию `be-calculator`. Доступ ко всем репозиториям для этой задачи не требуется.
4. Выберите свой репозиторий.
5. **Branch:** `main` (либо фактическая ветка с приложением).
6. **Primary file:** `app.R`.
7. Для первого запуска рекомендую отключить **Automatically publish on push**: так можно сначала проверить изменения, а затем вручную обновить опубликованную версию. Позднее автопубликацию можно включить.
8. Нажмите **Publish** и дождитесь завершения установки пакетов и запуска.

`renv.lock` уже подготовлен. **Создавать `manifest.json` дополнительно не нужно**: если оба файла присутствуют, Cloud отдаёт приоритет `manifest.json`.

Официальные инструкции: [публикация Shiny R](https://docs.posit.co/connect-cloud/how-to/r/shiny-r.html), [зависимости R](https://docs.posit.co/connect-cloud/how-to/r/dependencies.html).

## 5. Настройки приложения

- **Доступ:** в настройках Share проверьте **Public Access — Enabled**. На Free он включён по умолчанию. Посетителям публичного приложения не нужен аккаунт. [Описание доступа](https://docs.posit.co/connect-cloud/user/share/index.html).
- **Ресурсы:** для начала используйте 1 CPU и 2 GB RAM, если такой выбор доступен на вашем плане. Код запускает основной процесс R и одного фонового работника. Если установка или запуск завершается нехваткой памяти, увеличьте память в пределах плана и повторите публикацию. Проверки на конкретной Cloud-конфигурации выполняются после первого размещения.
- **Переменные/секреты:** обязательных нет. Часовой пояс даты расчёта — `Europe/Moscow`. При необходимости задайте переменную `BE_TIMEZONE`, например `UTC`, и перезапустите приложение.
- **Название:** задайте понятный заголовок «Калькулятор выборки БЭ». Собственный домен для начала не требуется.

Настройки CPU/RAM влияют на расход вычислительных кредитов даже при неполной загрузке выделенных ресурсов. Начинайте с небольшой конфигурации и смотрите фактическую память/использование. [Правила расчёта usage credits](https://docs.posit.co/connect-cloud/user/usage.html).

## 6. Проверка публичной ссылки

1. Откройте адрес самого приложения, обычно вида `https://<content-id>.share.connect.posit.cloud`, в приватном окне браузера без авторизации.
2. Проверьте стандартный пример: N = 28, с выбыванием N = 32.
3. Выберите «Высоковариабельный ЛП», оставьте настройки по умолчанию: 2×2×3, CVwR Cmax = 40%, CV AUC = 25%, мощность 80%, выбывание 15%. При закреплённой версии PowerTOST ожидаются N = 46 и N = 56 с выбыванием.
4. Измените CV и убедитесь, что появилось предупреждение о необходимости пересчёта.
5. Проверьте график, логотип и кнопку «Копировать сводку». На HTTPS копирование должно работать; при запрете браузера текст можно выделить вручную.
6. Откройте калькулятор в двух независимых окнах и выполните расчёты: результаты должны оставаться отдельными, при занятости работника второй запрос может ждать.
7. Передайте другому человеку именно ссылку на приложение, а не страницу администрирования и не GitHub.

После этих проверок ссылку можно распространять.

## 7. Последующие обновления

1. Измените локальный код.
2. Выполните `source("tests/verify.R")`, проверьте интерфейс локально.
3. Обновите файлы на GitHub через **Upload files** или `git add .`, `git commit`, `git push`.
4. В Connect Cloud вручную запустите повторную публикацию, если автоматическая отключена.
5. Снова откройте публичную ссылку и проверьте стандартный расчёт.

Если менялись версии пакетов, сначала выполните `source("scripts/update_lockfile.R")`, затем повторите тесты и загрузите новый `renv.lock` вместе с кодом.

## 8. Бесплатный тариф и типичные ошибки

На Free есть месячный лимит usage credits. Начиная с первого периода, который начнётся 1 ноября 2026 года или позже, при исчерпании лимита приложение перестаёт запускаться до следующего периода либо смены плана. Текущую квоту смотрите в **Account Usage / Plan overview**. Бесплатный тариф подходит для старта, но не гарантирует неограниченную работу при любой посещаемости. [Условия использования](https://docs.posit.co/connect-cloud/user/usage.html).

- **Не найден app.R:** проверьте корень репозитория и Primary file. Для этой версии путь — `app.R`.
- **Не найдены зависимости:** проверьте, что `renv.lock` закоммичен и выбранная ветка содержит последнюю версию. Не подменяйте его вручную списком пакетов.
- **Проблема сборки пакета:** откройте журнал deployment, сохраните название пакета и текст ошибки; Windows-папку `.Rlibrary` на Linux-хостинг загружать не нужно.
- **Нет логотипа:** проверьте точное имя `www/farm_logo.png` и регистр букв.
- **Ожидание расчёта:** один работник обслуживает очередь; ABEL рассчитывает симуляции. Если ошибка повторяется, проверьте журналы и память Cloud.
- **Лимит N / времени:** это ограничение публичного сервиса, а не вывод о невозможности исследования. Для такого сценария нужен отдельный локальный расчёт.
- **Приложение остановилось после периода использования:** проверьте остаток usage credits и журнал запуска.

Публикация на Cloud пока не выполнена; аккаунты, репозиторий и публичную ссылку создаёте по этой инструкции.
