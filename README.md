# Калькулятор размера выборки БЭ и эквивалентности ФК

Веб-приложение на R Shiny с расчётами через PowerTOST. Подготовленная копия исходного калькулятора для публикации на GitHub и Posit Connect Cloud. Исходная папка `BE_Calculator` не изменена.

## Быстрый запуск на своём компьютере

Откройте `BE_Calculator_Web.Rproj` в RStudio. В консоли R выполните:

```r
source("scripts/setup.R")       # один раз: установить версии из renv.lock
source("scripts/run_local.R")   # запустить калькулятор
```

Понадобится доступ в интернет при установке пакетов. Зависимости устанавливаются в локальную `.Rlibrary`, а не в общую библиотеку R. Для остановки приложения нажмите Stop в RStudio.

Команды предполагают, что рабочая папка — та, где лежит `app.R`.

**Публикация: [пошаговая инструкция](DEPLOYMENT.md).**

## Что рассчитывает приложение

- Семь сценариев: стандартный, высоковариабельный, NTI, длительное полувыведение, модифицированное высвобождение, эндогенное вещество, биотехнологический ЛП.
- ABE: `PowerTOST::sampleN.TOST()`; ABEL: `PowerTOST::sampleN.scABEL(regulator = "EMA")`.
- N по каждой выбранной конечной точке, максимум по точкам, заложенные минимумы и округление для баланса последовательностей.
- Выбывание: `N / (1 - dropout / 100)` с округлением вверх до кратного числу последовательностей.
- Мощность при итоговом N, чувствительность к CV/GMR, график мощности, копирование сводки и программного вывода.

α = 0,05. GMR задаётся сценарием: обычно 0,95 для стандартного ABE, 0,90 для ABEL, 0,975 для узких границ. Значения указаны рядом с каждым параметром; GMR в интерфейсе не редактируется.

Целевая мощность относится к отдельным конечным точкам. Максимум N по точкам **не является расчётом совместной мощности** всех критериев. Сценарии и методологические допущения унаследованы от исходного приложения. Назначение — предварительная оценка бюджета КИ; обоснование размера выборки для протокола требует отдельной работы биостатистика.

## Подготовка для публичного доступа

- `app.R` — стандартная точка входа; расчётная логика вынесена в `R/calculations.R`.
- По умолчанию выбирается перекрёстный 2×2, если он разрешён сценарием.
- Межиндивидуальный и внутрииндивидуальный CV имеют раздельные поля состояния.
- После изменения вводных появляется отметка, что показанный результат нужно пересчитать.
- У результата сохранены сценарий, дизайн, мощность, выбывание и фактическое время вычисления.
- При разных CVwT/CVwR оба значения видны в таблице и копируемой сводке.
- Один отдельный R-процесс выполняет вычисления; запросы разных сессий могут ожидать очереди.
- Последний успешный расчёт кэшируется только в памяти текущей пользовательской сессии.
- График ограничен 24 точками для ABE и 16 для ABEL, включает итоговый N.
- Публичная версия ограничивает анализируемый N значением 10 000 и выбывание диапазоном 0–90%.
- На расчёт задан лимит R 120 секунд. Это мягкий лимит: сторонний нативный код может отреагировать на него с задержкой; ожидание очереди в эти 120 секунд не входит.
- Версии зависимостей закреплены в `renv.lock`. Служебные файлы macOS не перенесены.

База данных не используется. Введённые значения отправляются серверу Shiny для расчёта; код приложения не записывает их в файлы. Хостинг может вести свои технические журналы.

## Структура

```text
app.R                       интерфейс и сервер Shiny
R/calculations.R            сценарии, ограничения, расчёты, сводка
www/farm_logo.png           логотип
renv.lock                   версии R и зависимостей
scripts/setup.R             восстановление зависимостей
scripts/run_local.R         локальный запуск
scripts/update_lockfile.R   обновление lock-файла после осознанного обновления пакетов
tests/verify.R              проверки расчётной логики
DEPLOYMENT.md               GitHub → Connect Cloud
VALIDATION.md               результаты и границы проверки
CHANGELOG.md                изменения по отношению к оригиналу
```

`.Rlibrary/` и `.renv-cache/` — локальные служебные каталоги, исключены из Git. Публиковать нужно исходники и `renv.lock`, а не установленные Windows-пакеты.

## Проверка и обновления

В консоли RStudio:

```r
source("tests/verify.R")
```

Из терминала, если Rscript доступен в PATH:

```text
Rscript tests/verify.R
```

После изменения кода повторите проверки. После намеренного обновления пакетов и успешных проверок выполните `source("scripts/update_lockfile.R")` и включите обновлённый `renv.lock` в тот же коммит.

Текущая проверенная среда: R 4.5.1, PowerTOST 1.5-7. Подробности: [VALIDATION.md](VALIDATION.md).
